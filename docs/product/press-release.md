# Colvenna Isle：S3 上的持久化分析数据库

Colvenna Isle 推出云端数据库与分析平台：通过 API 写入，在 S3 上完成 SQL 分析

**将数据接入、分层加工、SQL 查询、运行监控和访问管理整合为一个产品，为开发者与数据团队提供从业务数据到分析结果的完整工作流程。**

*下一版本产品发布文案 · 未发行 · 2026-10-24*

Colvenna Isle 推出基于 AWS 的云端数据库与分析平台。应用可以通过统一 API 写入订单、业务事件、日志和运营数据，数据团队可以使用 SQL 和 Python 完成清洗、建模与聚合，使用 SQL 查询分析结果，管理员可以在统一控制台中观察系统状态并管理访问凭证。产品以 Amazon S3 作为持久存储，通过原生引擎提供数据库与分析能力，将持续接入与分析处理连接起来。

从业务数据到可用指标，团队需要解决数据接入、重复请求、加工依赖、任务重试、数据新鲜度以及访问权限等问题。Colvenna Isle 将这些能力组织成统一的产品体验，使开发者、数据分析人员和管理员可以围绕同一个数据空间协作，并明确了解数据从写入到发布的每一步状态。

## 通过 API 持续接入业务数据

Colvenna Isle 提供批量数据写入 API，支持追加、更新和删除事件，并通过 schema 校验和幂等机制管理数据质量与重复请求。应用可以使用稳定的接入 ID 追踪一个批次，重试时沿用同一标识，避免重复请求造成重复业务数据。

接入队列缓冲突发流量，在写入服务重启或处理变慢时保留待处理批次。产品明确区分“已接收”“数据库已提交”和“分析版本已发布”，让调用者根据业务需要判断何时可以开始后续处理。过载请求收到明确背压，已确认批次继续保留。失败批次可诊断并在原权限和原身份下受控重放。需要确认提交结果的应用，可以查询接入状态；面向报表和指标的应用，可以进一步等待对应分析版本发布。

需要同步更新业务表时，应用可以对明确注册的直接写目标执行 insert/upsert/update/delete。成功回执表示整个批次已持久提交，并保留数据库原生约束；零行更新或删除也有确定的原回执。超时或响应丢失时，应用沿用原幂等身份查询和核对结果。同步提交与分析版本发布分别追踪。

## 数据持久保存在 S3，保留原生数据库能力

Colvenna Isle 使用对象存储扩展，将数据库及恢复所需日志保存在 Amazon S3，同时保留原生表、索引、约束、视图和 SQL 能力。应用使用统一的数据接口访问数据库，数据团队使用熟悉的 SQL 处理和分析数据。

分层业务表使用原生数据库存储。长任务需要的 Parquet 输入快照与计算结果另行保存，供任务复现、分块导入和结果导出使用。

存储与计算按职责组织。数据库写入、交互查询和长时间计算分别配置运行资源，查询服务可以按请求负载增加执行实例。每个数据库由一个活动写者负责变更，保证数据库所有权明确，并由产品统一调度批量接入、结果导入和版本发布。

## 用 SQL 和 Python 建立完整的分层数据流程

Colvenna Isle 支持在数据空间中组织 ODS、DWD、DWS、ADS：从原始业务记录，到清洗后的明细，再到主题聚合和面向应用的数据集。数据团队可以编写 SQL 转换或 Python 脚本，定义任务依赖，并通过定时运行、上游发布触发、手动回填、增量水位和失败重试管理数据流程。

流水线定义与运行管理集成在产品中。用户可以在控制台编辑和发布任务，也可以在 Git 等外部发布流程中调用 API，发布定义与代码。需要跨系统编排时，可以由 Airflow 调用运行 API，并等待分析结果发布。每条流水线明确指定自动调度方，版本与运行历史保持一致。

Python 任务支持 pandas 等包，用于自定义清洗、分类、计算和规则处理。包依赖在发布前解析、锁定并构建为运行环境；代码或依赖升级生成新版本，已有任务继续使用原版本。SQL 与 Python 任务使用明确的输入输出类型和固定数据版本，使计算结果可追溯。

每个任务可以分别选择增量处理、受影响分区重算或全量计算。例如，订单清洗只处理新变更，主题聚合读取已发布的完整明细；按日指标也可以只重算发生更新或删除的日期。任务记录输入水位和状态版本，在结果发布成功后推进进度。

每层数据都有可查询的处理水位与发布信息。用户可以了解一份指标覆盖到哪个批次、采用哪个输入版本，以及最近一次加工何时完成。1.1.0 中，一个数据空间的四层位于同一个数据库；按负载把接入明细与分析服务拆分为独立数据库是尚未实现的演进方向，设计上拆分后公开 API 保持不变。

## 长计算独立运行，分析结果按版本发布

有界 SQL/Python 任务可使用 Lambda 执行，大型关联、历史重算和主题聚合可配置独立 ECS 计算任务。输入绑定到固定数据版本，结果先暂存，再由写者分块导入。任务运行期间，用户可以继续查询上一版完整分析结果；新结果完成核对后，再切换到新的发布版本。

这一流程使数据团队能够追溯计算输入、转换版本和结果导入进度，并在失败时重试或重算。分块导入与接入批次协调调度，帮助管理长任务对写入资源的占用，避免将整个计算过程放入 API 请求的等待路径。

## 在 Query Editor 中编写和执行 SQL

Colvenna Isle 提供浏览器中的 Query Editor。用户可以浏览获授权的 schema、表和字段，编写 SQL，并使用目录补全和快捷键提交查询。编辑器支持只读 SQL 分析、执行计划查看、运行状态跟踪、查询取消和历史记录。

查询由独立查询服务执行，任务状态与浏览器连接分离。用户可以在结果表中浏览数据，并通过分页或导出获取较大的结果集。界面同时展示执行耗时和实际使用的数据版本，使分析人员能够判断结果的新鲜度，并将查询与相应的数据发布记录对应起来。

## 在 Admin Console 中管理状态与访问权限

Admin Console 提供统一的运行视图，展示写入服务的活动身份与心跳、最近提交、队列积压和最老消息年龄、各层水位，以及加工任务和查询的运行状态。指标附带采集时间，帮助管理员区分服务正在运行、数据已经提交和分析结果已经发布。

流水线页面集中管理任务依赖、SQL/Python 代码、运行参数、环境构建、版本发布和调度。用户可以查看每次运行的输入版本、执行状态、结果导入进度与发布历史，并按获授权的版本执行回填、取消或重试。

管理员可以创建、停用和轮换 API Key，为凭证指定数据空间、访问权限和到期时间。完整 key 仅在创建时展示，后续管理通过 key 标识、指纹、状态和使用记录完成。轮换流程允许先创建新凭证、完成调用方切换，再停用旧凭证。

产品 API 采用统一的 Bearer 认证方式：

```http
Authorization: Bearer <API_KEY>
```

数据写入、SQL 查询、流水线运行、监控和凭证管理使用各自的权限范围。管理者只能在获授权的数据空间和可委派权限内发放凭证，使应用接入与管理操作都有明确的访问边界。

## 面向应用开发与数据团队协作

Colvenna Isle 面向需要通过 API 汇集业务数据、建立 SQL/Python 加工流程并向应用提供分析结果的团队。典型场景包括订单与经营分析、业务事件分析、日志分析、运营指标，以及面向应用的聚合数据服务。

开发者通过 API 持续接入数据，数据团队通过 SQL 和 Python 构建可复用的数据集，管理员通过控制台管理运行状态和访问权限。接入回执、处理水位与发布版本贯穿整个流程，使团队能够从一笔写入追踪到其对应的分析结果。

产品前身的历史版本 1.0.0 于 2026-10-20 首次发行，1.1.0 于 2026-10-21 发行。Colvenna Isle 名称从下一版本采用，当前 `2.0.0.dev0` 尚未发行，改名后的 AWS 验收为 `NOT_RUN`。产品以一组 CloudFormation 栈部署在用户自己的 AWS 账号中，费用就是该账号中实际使用的 AWS 资源费用。历史 1.1.0 部署在单个 AWS 账号中、安装时指定的标准 AWS 商业区域（已在 `us-east-2` 与 `us-west-2` 验收），运行于 ARM64（Graviton），写者与查询服务规格为 2 vCPU / 4 GiB。支持矩阵、规格、限制与历史实测基线见[发行说明](../release-notes.md)和[性能与容量基线](../performance.md)；安装与使用方式见[安装部署手册](../installation.md)、[用户手册](../user-guide.md)和 [quickstart](../../examples/quickstart/README.md)。
